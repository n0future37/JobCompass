# 检索并发与缓存边界

普通搜索的准入仍为每进程最多 4 个执行中查询，等待 2 秒后返回 503，附 `Retry-After: 2`。单 IP 每分钟 60 次的规则独立返回 429。增加线程或延长等待不能代替减少请求实际工作量。

缓存键使用当前有效岗位的身份、内容指纹和版本生成语料指纹。MySQL 每次只查询这些字段，避免为生成键而解码全部 JD 正文。语料变化时，Retriever 重新加载岗位并建立 BM25 只读快照；正在执行的请求保留自己取得的快照引用，刷新不会混入另一个请求的数据。

硬条件检查按完整条件和语料版本缓存，最多 32 项；个人可见岗位范围在每次请求中单独相交，不存入共享条件缓存。返回的检查结果深复制，调用方不能改写后续请求的检查依据。BM25 使用词项倒排表计算相同公式，未改变排序目标。

共享锁只用于初始化客户端、切换快照和维护有界条件缓存，不锁住整个检索过程。MySQL 各次操作分别取得连接，Milvus 共享客户端执行独立请求。本地模型保留自身推理锁，避免在未验证模型并发安全时放开推理。

返回前批量复核候选的 MySQL 有效状态、版本和内容指纹，生成后再次检查；旧索引候选与新岗位版本不一致时不能直接展示。缓存键语料版本与实际检索快照不一致时，不写入该键。没有通过提高并发上限、取消版本检查或把错误转换成成功来提高压测成绩。

固定响应回归：`pytest tests/test_search_concurrency.py -q`。真实存储、模型推理和外部生成分别验证，合成语料与固定模型替身的吞吐不能代表 BGE 或真实模型端到端容量。
