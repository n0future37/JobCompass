# 系统架构

## 业务数据流

导入任务先校验完整文件，保存原件与幂等键。独立 worker 标准化岗位，以来源与来源 ID 维持身份，以内容指纹判断更新，保存不可变历史版本。MySQL 是权威数据源，Milvus 是可重建的检索索引。

检索先解析硬条件、软偏好与未支持条件。BM25 面向完整岗位文档，向量面向文本块；按岗位聚合后用 RRF 融合，BGE 重排。返回前再次核验 MySQL 有效状态和版本，避免下架或索引延迟造成旧结果。

## 推荐工作流

LangGraph 管理画像准备、条件过滤、检索、个性化排序与证据处理。LangChain 提供工具及调用封装。硬背景与当前条件先处理，缺失信息标记未知；软画像只影响可用候选的推荐顺序。

模型对完整候选 JD 只输出排序，引用理由按需生成；模型协议失败或超时回退到规则排序。生成只允许引用批准候选与片段，程序校验岗位、版本、行号和原文，再组装说明。画像缺少技能证据不会被解释成用户不会该技能。

## 存储与任务

| 组件 | 职责 |
| --- | --- |
| MySQL / SQLAlchemy / Alembic | 岗位版本、账号、画像、导入任务、历史、反馈与投递，约束与事务 |
| Milvus | 分块向量及派生索引，受有效状态与版本复核约束 |
| Redis | 请求限流、召回缓存及辅助状态，项目环境键前缀 |
| 独立 worker | 导入、分块与批量向量化，领取锁、幂等、租约和重试 |

缓存键包括语料与参数版本；岗位更新或下架后不复用旧内容。并发任务分别管理数据库连接。账号归属只由服务端会话确定，客户端不能指定其他账号的资源所有者。

## 安全与可观测性

密码采用加盐摘要，随机会话令牌只保存摘要；写操作校验请求来源。结构化日志关联请求 ID 与任务 ID，记录阶段耗时和异常。简历原件本地解析并私有存储；只有用户确认的允许字段用于个性化排序。查询可能发送到所配置的模型服务，前端有显式说明。

## 质量边界

职责证据检查用于避免关键词相似但工作方向错误；引用校验防止引用不存在或改写原文。逐字引用正确不等于语义推荐一定正确。固定模型响应的软件测试与真实模型检索评测分开，当前代理标签与合成画像不代表真实用户满意度。
